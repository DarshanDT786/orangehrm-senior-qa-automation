# Senior QA Automation Engineer Assessment — OrangeHRM

This repository contains a **TypeScript and Playwright automation framework** developed for the Senior QA Automation Engineer assessment. It uses the Page Object Model (POM) and includes employee lifecycle testing, API verification, role-based access test coverage, GitHub Actions CI, automated test reporting, and k6 performance-testing templates.

The framework includes retry configuration and failure diagnostics such as screenshots, traces, and videos to help investigate test failures.

**Note:** The project uses the public OrangeHRM demo environment. Test results and role-based access behavior depend on the availability and configuration of that environment. The role-access test requires valid ESS credentials, and the k6 scripts require a separately configured, authorized test environment.

## Tech stack

- Playwright Test + TypeScript
- Page Object Model (`src/pages`)
- Environment configuration via `.env`
- GitHub Actions with a two-shard matrix
- Playwright HTML/JUnit reports, trace, screenshot and video on failure
- k6 scripts with latency and error-rate thresholds

## Quick start

Requirements: Node.js 20 LTS (recommended), npm, and a supported OS.

Install dependencies and browsers:

```bash
cp .env.example .env
npm ci
npx playwright install chromium
npm run typecheck
npm test
```

Open the report after execution:

```bash
npm run report
```

Reports and failure artifacts are written under `artifacts/`. They are generated by running the tests and are intentionally not represented as pre-generated passing reports.

## Configuration

| Variable | Purpose | Default |
|---|---|---|
| `BASE_URL` | UI application base URL | OrangeHRM public demo |
| `API_BASE_URL` | API base URL | `BASE_URL` |
| `ADMIN_USERNAME` / `ADMIN_PASSWORD` | Admin login | Public demo credentials shown in `.env.example` |
| `ESS_USERNAME` / `ESS_PASSWORD` | Optional low-privilege role test account | Empty; role test is skipped |
| `K6_BASE_URL` | Base URL for performance API tests | `http://localhost:3000` |
| `K6_LOGIN_PATH` | Login API path for your target service | `/api/auth/login` |
| `K6_EMPLOYEE_PATH` | Employee creation API path for your target service | `/api/employees` |

Never commit real credentials. Put CI credentials in GitHub Actions Secrets and non-secret environment URLs in repository Variables.

## Test coverage

- `@smoke`: login/dashboard, PIM access, login page reachability.
- `@regression`: create employee, read employee via authenticated API, update employee, verify update via API, delete employee.
- `@role`: low-privilege account authorization check; requires a valid account with expected restricted permissions. The assertion may need to be aligned to the test tenant's actual role configuration.
- `@api`: reachability check for the login page. Employee API checks are part of the lifecycle flow so they reuse the authenticated browser session.

Run by tag:

```bash
npx playwright test --grep @smoke
npx playwright test --grep @role
npx playwright test tests/api
```

The role-based access test validates that a low-privilege ESS user cannot access restricted employee-management functionality. The test requires valid ESS credentials configured through environment variables or GitHub Actions Secrets.

## Architecture / design decisions

1. **POM:** page selectors and UI workflows are kept out of test assertions where practical.
2. **Unique test data:** each run creates a timestamp-based employee name to reduce collisions in parallel execution.
3. **State-aware synchronization:** Playwright locator auto-waiting and explicit visibility/value assertions replace fixed sleeps in UI flows.
4. **Reliability evidence:** CI retries twice; local execution retries once. Traces, screenshots, and videos are retained on failure.
5. **API verification:** API GET calls use the authenticated browser context so cookies are reused. Endpoint response shapes can vary by OrangeHRM version and must be confirmed against the assigned environment.
6. **Role testing:** role authorization is tenant-specific; the test requires a genuine least-privilege account.
7. **Performance isolation:** k6 targets are configurable templates. Their default endpoints are generic placeholders, not OrangeHRM endpoints. Do not execute against the public OrangeHRM demo without explicit permission and a target-specific plan.

## CI/CD

`.github/workflows/qa.yml` installs Node dependencies and Chromium, type-checks the project, runs two parallel Playwright shards, and uploads reports and failure evidence even when tests fail. Configure `ADMIN_USERNAME`, `ADMIN_PASSWORD`, `ESS_USERNAME`, and `ESS_PASSWORD` as GitHub Secrets when using a controlled environment. Set `BASE_URL` as a repository variable if needed.

## k6 performance checks (bonus)

Install k6 separately, then configure endpoints for a test API you own or are authorized to test:

```bash
K6_BASE_URL=https://your-test-api.example K6_LOGIN_PATH=/auth/login k6 run k6/login.js
K6_BASE_URL=https://your-test-api.example K6_EMPLOYEE_PATH=/employees k6 run k6/employee-create.js
```

The scripts emit the standard k6 summary, custom duration metrics, and thresholds. Adjust expected status codes, payload schema, authentication/token handling, test data cleanup, and thresholds to match the real API contract before using them as assessment evidence.
